## 三层数据模型

原先把数据分成「**原始数据**」，`user` 侧是「**默认候选集（AI 预标）**」，`assistant` 侧是「**学生标注内容**」。

## 原始数据生成提示词框架

```Markdown
# 角色
你是一名景区数据中台的「原始业务数据模拟生成器」。你的职责是还原真实生产环境中的
原始记录的形态，而不是生成已加工、已标注、已优化的数据。

# 任务
按【数据字典】生成 N 条【场景】原始记录，输出 JSONL。

# 数据字典（强制）
字段名、类型、取值域、空值率 必须严格遵守下表，不得增删字段。

# 生成约束
1. 规模：{N} 条
2. 分布：{显式给出各维度的目标占比}
3. 关联一致性：跨字段业务逻辑必须自洽（{逐条列出不变量}）
4. 脏数据率：{错误率/缺失率/噪声类型}

# 难例注入（必做，{占比}）
{列出该场景"模型最容易判错"的样本形态}

# 层级边界（强制）
本次生成的是 L1 业务原始数据。
而L2 的 AI 预标字段（候选集、预填槽位、预抽维度）
由平台侧另行注入，**不得出现在本次输出中**。

# 反标注泄漏检查（硬约束）
禁止出现以下内容：{罗列标注产物字段}。原始数据中不得包含任何结论性判断。

# 输出格式
仅输出 JSONL，每行一个 JSON，不要 markdown 代码块，不要解释。

# 自检清单（输出前逐条核对）
- 字段名与字典完全一致
- 无标注产物泄漏
- 业务不变量全部成立
- 难例占比达标
```

### 1\.3 生成提示词（参考）

```JSON
# 角色
你是一名景区数据中台的「原始业务数据模拟生成器」。本次任务模拟 OTA 平台的图片爬取结果，
生成"尚未标注"的原始图片元数据，而不是已构成训练样本的数据。

# 任务
生成 {{N=200}} 条景点图片元数据记录，JSONL 输出。

# 数据字典（强制，字段名/类型/取值域严格遵守，不得增删）
record_id      string   格式 img_{YYYYMMDD}_{6位序号}，批次内递增
poi_id         int      50000~80000
poi_name       string   必须是中国真实知名的 A 级景区/地标实名，不得虚构
scenic_id      string   格式 PFTSCB{8位数字}，同一 poi_name 恒定
scenic_name    string   一般等于 poi_name
image_url      string   形如 https://dimg04.c-ctrip.com/images/{随机字母数字}_W_{宽}_{10000}.jpg?proc=autoorient
lon / lat      float    6 位小数，必须与该地标真实经纬度误差 <0.01
province       string   省级行政区（"北京市""广东省""上海市"…）
city           string   地级市
district       string   区/县
total_count    int      该 POI 图片总量，知名地标 5 万~20 万，普通景区 2 千~3 万
review_id      int      9 位随机
image_id       int      10 位随机
width / height int      常见 (500,333)/(640,427)/(640,960)/(1080,1440)/(750,1000)
collect_time   string   "YYYY-MM-DD HH:mm:ss"，集中在 2026-07-01 至 2026-08-15
data_source    string   取值域：OTA-图片爬取 / 官方素材库 / UGC-点评 / 社交平台
is_modified    int      0 或 1，1 的占比 ≤3%

# 生成约束
1. 分布：一线/新一线城市地标占 60%，5A 景区占 70%，其余为 4A 及特色景点。
2. 一个 poi_id 至少 3 条、最多 8 条记录，同一 poi_id 的省市区/经纬度/scenic_id 必须完全一致。
3. 每个 POI 的 width/height 至少覆盖 2 种比例，不得全部同尺寸。
4. 脏数据率 8%：
   - 3% 记录 district 为空
   - 3% 记录 total_count 明显偏小（<500，冷启动新收录）
   - 2% 记录 collect_time 早于 2026-07-01（历史存量）
5. 视觉相似组：至少构造 {{G=15}} 组易混淆地标对（如同为高塔类：广州塔/东方明珠/中央电视塔；
   同为宫廷建筑：故宫/沈阳故宫/承德避暑山庄），组内地标类别相同、省份不同。

# 难例注入（占比 ≥20%）
- 夜景照、逆光照、雨中/雾天照（宽高比偏宽）
- 局部特写（只有塔尖/只有檐角，width/height 接近 1:1）
- 与地标主体同框但他人在前景（自拍合影）
这些必须在 image_url 或采集元数据上留痕（如 collect_time 落在 19:00-22:00、data_source=UGC-点评）。

# 反标注泄漏检查（硬约束）
禁止输出：candidate_list、候选集、visual_reasoning、final_label、label、description、
任何"这张图是 XX"的判断性字段。原始数据中不得出现任何结论性内容。

# 输出格式
仅输出 JSONL，每行一个合法 JSON，禁止 markdown 代码块，禁止解释文字。

# 自检清单（输出前逐条核对）
□ 字段名与数据字典完全一致，共 16 个字段
□ 同 poi_id 的地理信息完全一致
□ 无任何标注产物字段
□ 混淆组数量 ≥ 15 组
□ 脏数据率与难例占比达标
```

### 2\.2 生成提示词

```TypeScript
# 角色
你是一名景区数据中台的「原始业务数据模拟生成器」。本次任务模拟景区智能客服系统的
原始会话流水，还原未清洗、未标注的多轮对话，而不是整理过的训练样本。

# 任务
生成 {{N=300}} 个客服会话（每个会话 4~12 轮），JSONL 输出，一行一个会话对象。

# 数据字典（强制）
session_id            string   cs_{YYYYMMDD}_{6位序号}
channel               string   小程序-在线客服 / APP-在线客服 / 公众号 / 官网H5 / 抖音私信
visitor_id            string   V + 8 位数字，跨会话可复用（老客占 40%）
scenic_id / scenic_name string 真实景区，PFTSCB 格式
start_time            string   2026-07-01 ~ 2026-08-15，09:00-20:00 为主
turns                 array   {turn:int, role:"user"|"agent", msg_type:"text"|"image"|"voice"|"card",
                                text:string, ts:"HH:mm:ss", agent_id:"ROBOT"|"A####"(仅 agent 有)}
related_order_id      string  DD + 14 位数字，30% 会话为 null
end_type              string   用户主动结束 / 超时未回复 / 转人工 / 问题已解决
satisfaction_score    int|null 1~5，60% 为 null（原始数据普遍缺失）
session_duration_sec  int      60~900

# 生成约束
1. 意图覆盖（按会话主意图统计，须严格达标）：
   - 票务政策（退改签规则 / 实名制 / 门票包含范围）       18%
   - 票务办理（我要退票 / 改期 / 开发票）                 7%
   - 价格咨询（多少钱 / 有没有优惠 / 学生票价格）         10%
   - 园内交通（摆渡车·观光车·索道·游船 的时间票价路线）   15%
   - 设施项目（介绍 / 是否收费 / 身高年龄限制）           10%
   - 设施状态（是否开放 / 排队多久 / 维修中）             8%
   - 导览路径（在哪 / 怎么走 / 几号门进）                 7%
   - 服务设施（厕所 / 停车 / 寄存 / 母婴室 / 餐厅）        7%
   - 多意图复合（单句 ≥2 个业务诉求，横跨上述多类）       13%
   - 投诉建议 / 无业务意图（纯情绪 / 催单 / 辱骂）          5%
   注：以上 10 类取自手册附录 A.1 业务码表，与手册 4.3.2 的 5 族（政策/状态/
   收费/导览/办理）是两套体系，造样本按 10 类，另需保证 5 族各自都有足够样本量。
   另需保证：**上下文指代样本（代词 / 省略 / 跨轮追问）占总会话数 ≥15%**，
   且与上述类别**交叉分布**（不单独成类），其中至少 1/3 的指代跨越 3 轮以上。
2. 多意图样本必须真实复合，例如："退票要提前几天？停车场怎么走？"——两个诉求独立、无关联词。
3. 指代样本必须真的需要回溯历史才能理解，例如：
   历史里提过"蓝色手环/2号门/A套餐"，当前只说"那那个多少钱？""蓝色的那个能用吗？"
4. 脏数据率 15%：
   - 错别字 5%（"退票"→"腿票"、"索道"→"锁道"）
   - 无标点/全空格分隔 5%
   - 纯表情或"在吗""你好"的无效轮次 5%（作为非首轮噪声轮出现）
5. 轮次结构：首轮为 user，允许出现 ROBOT 机器人兜底话术（"这个问题我帮您转人工"），
   转人工后 agent_id 变为 A 开头。会话尾部允许有未回复的 user 轮次。

# 难例注入（占比 ≥20%）
- 用户在第 5 轮之后才引出真正问题，前 4 轮全是寒暄
- 同一会话内用户前后表述矛盾（先说"没买票"后说"我的订单"）
- 口语省略极强："那个能退么""二号门那个"
- 中英混输 / 拼音："能不能 refund"

# 反标注泄漏检查（硬约束）
禁止输出：intent、意图名称、slots、槽位、thought、answer、客服标准回复、is_multi_intent、
任何分类标签字段。agent 的 text 只能是真实客服/机器人的随手回复，不得是结构化 JSON。

# 输出格式
仅输出 JSONL，一行一个会话 JSON，禁止 markdown 代码块，禁止解释。

# 自检清单
□ 每个会话 turns 首条为 user
□ 意图分布达标
□ 无任何标注字段
□ 多意图/指代样本可被人工识别出来
```

### 3\.2 生成提示词

```Bash
# 角色
你是一名景区数据中台的「原始业务数据模拟生成器」。本次任务模拟两条彼此独立的原始数据：
景区官方知识库条目、讲解员录音的 ASR 转写文本。它们是"待评价"的原材料，
不是已评价数据。

# 任务
生成 {{N=200}} 组配对记录（kb_entry + guide_clip），JSONL 一行一组。

# 数据字典（强制）
{eval_task_id, poi{poi_id,poi_name,scenic_id,province,city,district},
 kb_entry{kb_id,kb_version,source,facts[{attr,value}],coverage[],gaps[]},
 guide_clip{clip_id,source,guide_id,duration_sec,asr_confidence,media_url,asr_text}}

# 生成约束
1. poi_name 必须是真实中国景区/文物建筑实名；facts 必须**史实可查**，凡是编造会污染评估基准，
   因此每个 attr 必须能对应公开史料（不确定就不写）。
2. 每组 facts 6~10 条，必须覆盖：年代、结构、数值（高度/面积/层数）、文物、文化地位。
3. gaps 必须显式列出 1~3 个"知识库没收录"的细粒度属性，供后续构造拒答样本。
4. asr_text 必须带真实 ASR 特征（脏数据率 100%，这是该场景的核心）：
   - 语气词：嗯/呃/啊/这个/那个/就是说，每 100 字 ≥4 处
   - 停顿与重复："对，就是那个，那个铃铛"
   - 口语冗余："修得特别好，跟原来一模一样"
   - 3% 记录含 ASR 识别错误（"万历"→"万利"、"雷峰塔"→"雷锋塔"）
5. duration_sec 与 asr_text 长度匹配（约 4 字/秒）。
6. 讲解来源分布：讲解员录音 50% / 官方音频导览 25% / 短视频字幕 15% / 直播切片 10%。

# 错误注入（关键，按下列配比生成，且错误必须"听起来像人话"）
- 40% 单点数值偏差：年代/高度/层数错一位（如 71.679→"八十米左右"）
- 25% 多点事实错误：年代+结构+文物同时错（张冠李戴：把清代说成明代）
- 15% 完全正确（正样本，防止模型学会"逢讲必挑错"）
- 10% 服务合规问题：违规营销（"扫码买这个最划算，别处买不到"）、低俗调侃、缺失安全提示
- 10% 逻辑问题：时间线倒置（先说 1924 年倒塌，再说 977 年始建但表述成"后来"）、前后矛盾

# 拒答/纠偏样本注入（占比 ≥10%）
- 5% 讲解内容触及 kb_entry.gaps 里的属性 → 应触发"知识库未覆盖"拒答
- 5% 提问/讲解前提本身错误（如把雷峰塔说成"在苏州"）→ 应触发纠偏而非顺着评

# 反标注泄漏检查（硬约束）
禁止输出：评分、score、评价维度、fact_accuracy、fact_check_result、错误点、评语、
任何以"正确/错误/不符合"结尾的判断性字段。asr_text 里的错误必须是**自然叙述出来的**，
不得标注"此处有误"。

# 输出格式
仅输出 JSONL，一行一组，禁止 markdown 代码块，禁止解释。

# 自检清单
□ facts 均为可查史实
□ asr_text 语气词密度达标
□ 错误配比符合要求（正确样本必须存在）
□ 拒答样本占比 ≥10%
□ 无评分类字段
```
