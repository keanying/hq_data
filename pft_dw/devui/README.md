# PFT 2.0 数据开发平台（devui）

在数据开发平台 demo 的基础上接入 PFT 2.0 数仓：后端改为 **Python 标准库 + SQLite**，项目里预置了 “PFT 2.0 数仓项目”。项目中包含全部开发任务、调度工作流、数据质量规则和字段血缘。

## 启动

```bash
cd pft_dw/devui
python3 server/app.py              # 打开 http://127.0.0.1:4180
python3 server/app.py --port 8080 --host 0.0.0.0
python3 server/app.py --reseed     # 数仓生成器更新后，用最新结果重建 PFT 项目（会覆盖该项目的改动）
```

Windows 双击 `启动.bat`。需要 Python 3.9 或更高版本，不依赖第三方包，也不需要 Node。数据库文件在 `data/devui.db`，首次启动时自动创建；该目录不进 git。排布规则升级后，启动时会自动更新已有 PFT 项目里工作流的分组和坐标，任务代码、连线、自己加的节点和分组的展开/收起状态都保留，不需要 `--reseed`。

## 项目内容

| 位置 | 内容 |
|---|---|
| 工作流 / 日调度 · 主流程 | `源库就绪 → ODS → DWD → DWS → ADS → 对账 → 发布`。DIM 是分支：ODS → DIM → DWD/DWS/ADS。分组是两层嵌套：外层是一个分层（ODS、DWD、DWS、ADS、DIM 分支），里面是这一层的各个数据域。数据域分组默认收起；组内的任务和它的质检节点成对排列。把分层外框都收起后，画布上只剩主线上的几张卡片 |
| 工作流 / 实时 · Flink 作业 | `ODS(CDC) → DWD → DWS → ADS`，加一列 Flink 作业监控。实时任务查询的离线维表作为分支放在下方 |
| 工作流 / 周、月、年调度 | 开始 → 任务 → 质检 → 结束 |
| ODS / DIM / DWD / DWS / ADS | 离线任务，按数据域分子目录，共 219 个 |
| 实时作业 | 实时任务，按分层分目录，共 54 个 |
| 数据质量 | 质检任务，按分层分目录，另有「对账」「实时监控」「作业监控」 |
| 调度控制 | 各调度的开始节点（源库就绪检查）和结束节点（数据就绪发布），Shell 任务 |
| 数据运维 / 周期任务 | 已配置日、周、月、年四个周期调度 |

- 分组：卡片上不再有展开按钮，双击分组标题或收起后的卡片即可展开或收起。分组可以嵌套：选中若干分组或任务后右键「将选中任务创建分组」，被完整选中的分组会成为新分组的子分组；如果选中内容都在某个已有分组内，新分组也会自动放进那个分组。「解除分组」后，子分组会上移一层。
- 排布是网格：泳道（分层）沿流向排列，每一行是一个数据域，同一数据域在各层对齐，主线是一条直线。缩放条左侧有两个开关：「布局」可切换左→右或上→下，所有工作流都可以切换（普通工作流按卡片宽高比整体转置）；「连线」可切换折线或曲线。两项设置都按工作流分别保存。分组折叠或展开后整张网格重新计算，不会重叠；右键菜单里的「自动布局」也按这套规则执行。
- 折线模式下：
  - 同一个通道里，不同来源的竖线各占一条轨道，互不重叠；同一来源的线共用一条主干。
  - 汇入同一目标的横线合成一条总线。
  - 所有连线都从卡片的出口圆点画出，画入入口圆点。
  - 开始、结束节点的线属于调度控制，画成灰蓝色虚线；DIM 分支的线是紫色虚线。
- 「实时/离线对账」只依赖 DWS，与 ADS 并列放在 ADS 一列（ADS 外框之外）。
- 依赖分层：
  - 没有上游的任务是第 1 层，其余任务的层级是“所有上游里最大的层级 + 1”；同一层内按上游位置排序，以减少交叉。
  - 展开分组时，组内任务自动按层级重新排列；右键分组也可以选「按依赖分层排布」。「自动布局」对整个工作流按层级排布。
  - 同一泳道里互相依赖的数据域，会按层级分成前后几列。
  - DIM 分支内部也按层级排列。
  - 每张卡片右上角标出它在所在分组（或整个工作流）里的层级 L1、L2……，可以用缩放条旁的「层级」按钮开关。
- 参数设置面板默认收起成右侧窄条，鼠标移上去展开、移开收起；点 ‹ 可以固定展开。每个参数都有“描述”一栏，PFT 项目的日期参数已经预先写好了描述。
- 拖动卡片或分组时，连线实时跟着变：
  - 曲线模式：端口到端口的平滑曲线；目标在后方时画成 S 形。
  - 折线模式：目标在前方走中线；在后方或并排时，从两卡之间或外侧绕开。
  - 只有“泳道之间、目标在前方”的线走泳道通道。通道位置取自排布时记录的泳道几何（`layout.geo`），每条线的轨道也是固定的。
  - 因此拖动一张卡片只会改变它自己的连线，其他连线不动。卡片被拖出所属泳道后，它的连线改为按实际位置走。
- 连线只改画法，不改依赖：
  - 走泳道之间的空隙，用圆角折线。
  - 跨层的线走行与行之间的通道；DIM 分支的线是浅紫色虚线。
  - 依赖照实画：E 直接依赖 A、B，就画 A→E 和 B→E。分组收起后，组内外的多条线收敛成“组—组”或“组—任务”之间的一条线；两边都是收起的分组时，只剩一条线。
- 点击任务或分组后，与它直接相连的线会按数据流向流动：橙色是流入的上游，蓝色是流出的下游，平时隐藏的冗余线也会显示出来。相邻的卡片会描边，其余连线照常静态显示，左下角显示上游、下游各有几条。点击空白处或按 Esc 取消。系统开启“减少动态效果”时只变色，不流动。
- 在画布上拖动画布、节点或分组时，不会选中页面上的文字。
- 双击任务进入开发页。顶部五个标签：
  - **开发代码**：可编辑、可保存。
  - **表 DDL**：建表语句。
  - **字段与血缘**：每个字段的类型、角色、加工口径，以及上下游字段。点击表名直接打开对应任务。
  - **质量规则**：每条规则的 SQL、期望值、强弱级别。
  - **调度依赖**：所属调度、cron、SLA、重试、上下游节点。

## 任务代码怎么来的

`server/codegen.py` 按字段血缘和口径文字为每张表生成代码：

| 分层 | 代码 |
|---|---|
| 离线 ODS | Spark SQL：JDBC 临时视图读业务库（`_di` 按 update_time 增量，`_df` 全量），再 `INSERT OVERWRITE` 分区；证件号、手机号脱敏 |
| 离线 DIM / DWD | 主表加关联表，逐字段翻译口径（改名、÷100 转元、取日期、JSON 展开、按 X 汇总等）。关联键从口径里的“按 X 关联”推断，主表上找不到时沿已关联的表链式推断。`_zip` 表生成闭链/开链模板 |
| 离线 DWS | 每个来源表一段聚合 CTE，`UNION ALL` 后按粒度汇总，再关联维度属性 |
| 离线 ADS | 把 DWS 字段按统计周期（1d / 7d / 30d / mtd / ytd / td）开窗求和作为基数，再组合成派生指标（比率、差值、均值） |
| 实时 ODS | Flink CDC 源表定义 |
| 实时 DWD / DWS / ADS | Flink SQL：临时视图加 StarRocks 结果表。维表用 `FOR SYSTEM_TIME AS OF` 查询 Hive 维表。分钟窗口按事件时间取整后分组聚合，写入主键模型（upsert） |
| 质检 / 对账 | 规则 SQL 逐条列出，并写明期望值和强弱级别 |

口径文字无法确定的字段，生成器不会猜。这类字段写成 `CAST(NULL …)`，并加注释 `-- TODO 口径：<原口径>`，目前共 676 处。主要有三类：

- 状态变化与镜像类，如“首次变为 PAID 的时间”“binlog 前镜像”。
- 去重人数跨天累加：这类指标不能直接求和，需要回到 DWD 去重。
- 同一个 DWS 字段被 ADS 按不同业务条件拆分（例如退款发起方），DWS 的粒度不足以区分。

另有 8 处关联键无法推断，生成了 `ON 1 = 0 /* TODO 关联键 */`。

参数约定：`${bizdate}` 为 YYYYMMDD，此外还有 `${bizdate_dash}`、`${bizdate_prev}`、`${bizdate_begin}` / `${bizdate_end}` 和 `${bizdate_minus_7}`。这些参数已写在各离线工作流的参数里。数据源连接（`${jdbc.*}`、`${mysql.*}`、`${cdc.*}`、`${starrocks.*}`）属于环境配置，不放在任务参数中。

## 后端

| 接口 | 说明 |
|---|---|
| `GET /api/kv` | 页面启动时取回全部存储键：项目列表、各项目开发草稿、定时运行、即席查询草稿 |
| `PUT /api/kv/<key>` / `DELETE` | 写入一个键 |
| `GET /api/meta/task/<任务标识>` | 开发页的 DDL、字段血缘、质量规则、调度依赖 |
| `GET /api/meta/summary` | 元数据概况 |
| `POST /api/jars?name=x.jar` / `GET /api/jars/<id>` | JAR 程序包上传（≤50 MB）与下载 |

**保存与提交：**
- 开发页的自动保存只写入浏览器本地草稿（IndexedDB），不进数据库。工具栏「提交」按钮出现橙点，表示有未提交的修改。
- 点「提交」或按 Ctrl+S，才会写入数据库。
- 刷新页面或重新打开时，会优先恢复未提交的本地草稿；「放弃修改」会回到数据库里最后一次提交的版本。
- 项目的新建/删除、定时运行配置、即席查询本身就要在对话框里确认，确认后直接写入数据库。

**撤销与重做：**
- 工具栏有 ↶ / ↷ 按钮，也可以用 Ctrl+Z 撤销，Ctrl+Shift+Z 或 Ctrl+Y 重做。
- 撤销历史保存在当前浏览器标签页的会话里（IndexedDB，gzip 压缩）。不论是自动保存过，还是刷新了页面，只要没关掉这个标签页，都能继续撤销。
- 提交到数据库后同样可以撤销，撤销后需要再次提交。
- 新开一个标签页或浏览器，就是新的会话，撤销历史从空开始。

前端原本把数据存在 localStorage。`web/backend.js` 在页面启动时从后端取回全部数据，之后对 `dataflow-*` 键的读写都转发到后端；后端不可用时自动退回浏览器存储。其中两类键在 SQLite 里拆成关系表存储：

- 项目列表 → `project`
- 开发草稿 → `folder` / `task` / `flow` / `flow_node` / `flow_edge` / `flow_group`

其余键存在 `kv` 表。数仓元数据存在 `dw_table` / `dw_column` / `dw_flow` / `dw_node` / `dw_rule` 表，每次启动时从 `pft_dw/web/*.json` 刷新，只读。

测试：`python3 -m unittest discover -s tests`

## 改了 demo 的哪些地方

- `web/backend.js`：新增，负责存储转发。
- `web/pft-meta.js`、`web/pft-meta.css`：新增，开发页的数仓信息标签。
- `web/project-storage.js`：引入后端；空项目增加 ODS 目录。
- `web/model.mjs`：分层增加 ODS；新增 `relayout`（网格泳道排布，支持横向和纵向），与 `server/seed_pft.py` 采用同一算法，有测试保证两边结果一致。
- `web/flow-view.mjs`：新增，负责连线走线、去掉冗余线、选中高亮。
- `web/app.js`：连线改由 `flow-view.mjs` 计算；增加排布方向按钮；纵向排布时连接点移到卡片上下；折叠分组和自动排布时调用 `relayout`；打开任务时广播事件；支持从血缘标签跳转任务；保存提示改为“服务器 · SQLite”。
- `web/development.js`：切换项目前先等待未完成的保存写完。
- 删除 `serve.mjs` / `package.json`，由 `server/app.py` 提供静态文件和接口。
